# Error Correction Exercise Generator

正しいC/C++プログラムから、誤り修正問題を自動生成するプロトタイプです。

この制作物は、学習者に「コンパイルは通るが、実行結果が正しくないC/C++プログラム」を提示し、行ごとに確認しながら修正してもらうためのものです。問題生成時には、正しいプログラムをテスト入力で実行して期待出力を作り、その期待出力と違う結果になる誤りだけを問題として採用します。

## 何ができるか

- 正しいC/C++プログラムから、誤り入りの修正問題を生成できます。
- 問題コードは全行を同じ見た目で表示し、確認済みの行だけを緑色にできます。
- 生成される誤りは、原則としてコンパイルエラーではなく、コンパイルは通るが出力が違うロジック誤りです。
- 解答時には、修正後のC/C++コードをコンパイル・実行して採点します。
- 1回目で不正解だった場合、C++コードには `cout` による追跡出力を追加し、期待出力も追跡出力込みに更新できます。
- 問題コードの隣に各テストケースを表示し、採点後は期待される出力と実際の出力を横並びで確認できます。

## 操作の流れ

画面上部の「操作ガイド」に従って進めます。ガイドの「次へ」「戻る」を押すと、今操作する場所がハイライトされます。

### 1. 正しいC/C++プログラムを貼り付ける

最初に、問題生成の元になる正しいC/C++プログラムを入力します。

ここには、すでに誤りを含んだコードではなく、期待通りに動く正解コードを入れてください。

例えば、次のコードはすでに誤り入りです。

```c
for (i = 0; i < size - 1; i++) {
  if (data[i] > avr) {
```

この場合、正しい版を入力します。

```c
for (i = 0; i < size; i++) {
  if (data[i] >= avr) {
```

### 2. テスト入力を書く

次に、C/C++プログラムに標準入力として渡す値を書きます。複数のテストケースを使う場合は、`---` だけの行で区切ります。

```text
1 2 3 4
---
5 5 5
---
-2 -1 0 10
```

固定回数の `scanf` があるプログラムでは、各テストケースに必要な個数の値が入っているかを検査します。

例えば、次のように2回入力を読むプログラムなら、

```c
scanf("%d", &age);
scanf("%lf", &height);
```

各テストケースには少なくとも2つの値が必要です。

```text
18 170.5
---
20 165.0
```

### 3. 最大誤り数を決める

最大誤り数は、生成時に埋め込む誤り候補の上限です。

指定した数だけ必ず生成されるわけではありません。候補のうち、実際にコンパイルが通り、テスト出力が正解と異なるものだけが採用されます。

### 4. 問題生成を押す

「問題生成」を押すと、次の処理が行われます。

1. 正しいC/C++プログラムをコンパイルする
2. テスト入力で実行して期待出力を作る
3. 誤り混入ルールを使って候補を作る
4. 候補ごとにコンパイル・実行する
5. コンパイルが通り、出力が期待出力と異なる候補だけを採用する

生成に成功すると、誤り入りのコードが行ごとのエディタとして表示されます。

### 5. 行ごとに確認しながら修正する

生成された問題では、すべての行を直接編集できます。

上から順に読み、OKだと思った行には左のチェックを入れて緑色にできます。必要だと思う箇所を正しいコードに修正してください。

### 6. 解答する

修正できたと思ったら「解答」を押します。

採点では、修正後のC/C++コードをコンパイルし、問題生成時と同じテスト入力で実行します。その出力が、正しいプログラムから作った期待出力と一致すれば正解です。

各テストケースは問題コードの隣に表示されます。採点後は「期待される出力」と「実際の出力」が隣り合わせで表示されるため、差分を見比べながら修正できます。

不正解だった場合は「coutヒント」を押すと、表示中の問題コードと正解コードに同じ追跡用 `cout` を追加します。追加された `cout` の行は、コード上でわかるように行全体がハイライトされ、出力には `[trace L10]` のように対応する行番号も表示されます。このとき各テストケースの期待出力も `cout` の出力込みで作り直されるため、次の採点では途中経過を含めて比較できます。

追跡用 `cout` は、主に `sum`・`size`・`avr` の更新直後、範囲forの各周回の先頭、`count++` や `count += ...` などの `count` 更新直後に追加されます。

失敗した場合は、次のようにテストケースごとに確認できます。

```text
case 2
入力
5 5 5

期待される出力
平均: 5.000000
平均以上は3個

実際の出力
平均: 5.000000
平均以上は0個
```

## 誤り混入ルール

ルールは [`rules/error-rules.json`](rules/error-rules.json) に定義しています。

現在は、主に次のカテゴリを扱います。

- ループ境界バグ
- 初期値バグ
- 比較演算子バグ
- 算術演算子バグ
- 出力変数取り違え
- 配列添字バグ
- 論文図7に由来する誤り混入ルールの一部

## 現在の制限

- C/C++構文を完全に解析しているわけではなく、正規表現ベースのルール適用です。
- どんなC/C++プログラムでも必ず問題を生成できるわけではありません。
- 入力・分岐・ループ・配列・計算・出力を含む初心者向けC/C++プログラムを主な対象にしています。
- テスト入力が弱いと、誤りを入れても出力差が出ず、候補が採用されないことがあります。
- 配列添字バグなどは実行時の未定義動作を起こし得るため、コンパイル・実行検査で落とす方針にしています。
