# Error Correction Exercise Generator

正しいCプログラムから、誤り修正問題を自動生成するプロトタイプです。

入力された正しいプログラムをテスト入力で実行して期待出力を作り、その後、コンパイルは通るが出力が変わるような誤りを埋め込んだ問題を生成します。解答時は、学習者が修正したCコードをコンパイル・実行し、期待出力と比較して正誤判定します。

## 現在の仕様

- 正しいCプログラムを入力できます。
- テスト入力を `---` 区切りで複数指定できます。
- 正しいCプログラムを実行して、各テスト入力に対する期待出力を自動生成します。
- 誤り混入ルールから、コンパイルが通り、かつ出力が期待出力と異なる候補だけを採用します。
- 誤り箇所は黄色の編集可能ブロックとして表示されます。
- 解答時は、修正後のCコードをコンパイル・実行して採点します。
- 採点結果には、各テストケースの入力、期待される出力、実際の出力を表示します。
- 最大誤り数とシードを指定して、問題バリエーションを調整できます。

## 入力欄

### 正しいCプログラム

問題生成の元になる正解コードを入力します。

ここには、すでに誤りを含んだコードではなく、期待通りに動く正しいコードを入れます。たとえば、次のような誤り入りコードを入れると、それが正解として扱われます。

```c
for (i = 0; i < size - 1; i++) {
  if (data[i] > avr) {
```

この場合、正しい版を入力します。

```c
for (i = 0; i < size; i++) {
  if (data[i] >= avr) {
```

### テスト入力

Cプログラムの標準入力として渡す値を指定します。複数ケースは `---` だけの行で区切ります。

```text
1 2 3 4
---
5 5 5
---
-2 -1 0 10
```

固定回数の `scanf` があるプログラムでは、各ケースに必要な個数の値が入っているかを検査します。

### 最大誤り数

生成する黄色ブロックの最大数です。指定した数だけ必ず生成されるとは限らず、実際にコンパイルが通り、出力差が出る候補だけが採用されます。

### シード

問題生成のランダム性を固定する値です。同じ正しいプログラム、同じテスト入力、同じシードなら、同じ問題を再生成しやすくなります。空欄の場合は毎回ランダムに近い形で生成されます。

## 誤り混入ルール

ルールは [`rules/error-rules.json`](rules/error-rules.json) に定義しています。

現在は、主に次のカテゴリを扱います。

- ループ境界バグ
- 初期値バグ
- 比較演算子バグ
- 算術演算子バグ
- 出力変数取り違え
- 配列添字バグ
- 論文図7に由来する誤り混入ルールの一部

生成器は、ルールをそのまま採用するのではなく、候補ごとに以下を確認します。

1. 誤り入りCコードを作る
2. コンパイルできるか確認する
3. テスト入力で実行する
4. 正しいプログラムの期待出力と異なるか確認する
5. 条件を満たす候補だけを黄色ブロックとして採用する

そのため、コンパイルエラーになるだけの誤りは原則として問題に採用されません。

## 現在の制限

- C構文を完全に解析しているわけではなく、正規表現ベースのルール適用です。
- どんなCプログラムでも必ず問題を生成できるわけではありません。
- 入力・分岐・ループ・配列・計算・出力を含む初心者向けCプログラムを主な対象にしています。
- テスト入力が弱いと、誤りを入れても出力差が出ず、候補が採用されないことがあります。
- 配列添字バグなどは実行時の未定義動作を起こし得るため、コンパイル・実行検査で落とす方針にしています。
