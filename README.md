# Error Correction Exercise Generator

正しいCプログラムから、誤り修正問題を自動生成するプロトタイプです。

この制作物は、学習者に「コンパイルは通るが、実行結果が正しくないCプログラム」を提示し、色付きの編集可能ブロックを修正してもらうためのものです。問題生成時には、正しいプログラムをテスト入力で実行して期待出力を作り、その期待出力と違う結果になる誤りだけを問題として採用します。

## 何ができるか

- 正しいCプログラムから、誤り入りの修正問題を生成できます。
- 誤りは色付きの編集可能ブロックとして表示されます。
- 生成される誤りは、原則としてコンパイルエラーではなく、コンパイルは通るが出力が違うロジック誤りです。
- 解答時には、修正後のCコードをコンパイル・実行して採点します。
- 採点結果では、各テストケースの入力、期待される出力、実際の出力を確認できます。

## 操作の流れ

画面上部の「操作ガイド」に従って進めます。ガイドの「次へ」「戻る」を押すと、今操作する場所がハイライトされます。

### 1. 正しいCプログラムを貼り付ける

最初に、問題生成の元になる正しいCプログラムを入力します。

ここには、すでに誤りを含んだコードではなく、期待通りに動く正解コードを入れてください。

例えば、次のコードはすでに誤り入りです。

```c
for (i = 0; i < size - 1; i++) {
  if (data[i] > avr) {
```

この場合、正しい版を入力します。

```c
for (i = 0; i < size; i++) {
  if (data[i] >= avr) {
```

### 2. テスト入力を書く

次に、Cプログラムに標準入力として渡す値を書きます。複数のテストケースを使う場合は、`---` だけの行で区切ります。

```text
1 2 3 4
---
5 5 5
---
-2 -1 0 10
```

固定回数の `scanf` があるプログラムでは、各テストケースに必要な個数の値が入っているかを検査します。

例えば、次のように2回入力を読むプログラムなら、

```c
scanf("%d", &age);
scanf("%lf", &height);
```

各テストケースには少なくとも2つの値が必要です。

```text
18 170.5
---
20 165.0
```

### 3. 最大誤り数を決める

最大誤り数は、生成する色付きブロックの上限です。

指定した数だけ必ず生成されるわけではありません。候補のうち、実際にコンパイルが通り、テスト出力が正解と異なるものだけが採用されます。

### 4. 問題生成を押す

「問題生成」を押すと、次の処理が行われます。

1. 正しいCプログラムをコンパイルする
2. テスト入力で実行して期待出力を作る
3. 誤り混入ルールを使って候補を作る
4. 候補ごとにコンパイル・実行する
5. コンパイルが通り、出力が期待出力と異なる候補だけを採用する

生成に成功すると、誤り候補が色付きブロックとして表示されます。

### 5. 色付きブロックを修正する

生成された問題では、色付きブロックをクリックして編集できます。

必要だと思う箇所を正しいコードに修正してください。すべてのブロックを必ず編集する必要はありません。編集しない方が正しい場合もあります。

### 6. 解答する

修正できたと思ったら「解答」を押します。

採点では、修正後のCコードをコンパイルし、問題生成時と同じテスト入力で実行します。その出力が、正しいプログラムから作った期待出力と一致すれば正解です。

失敗した場合は、次のようにテストケースごとに確認できます。

```text
case 2
入力
5 5 5

期待される出力
平均: 5.000000
平均以上は3個

実際の出力
平均: 5.000000
平均以上は0個
```

## 誤り混入ルール

ルールは [`rules/error-rules.json`](rules/error-rules.json) に定義しています。

現在は、主に次のカテゴリを扱います。

- ループ境界バグ
- 初期値バグ
- 比較演算子バグ
- 算術演算子バグ
- 出力変数取り違え
- 配列添字バグ
- 論文図7に由来する誤り混入ルールの一部

## 現在の制限

- C構文を完全に解析しているわけではなく、正規表現ベースのルール適用です。
- どんなCプログラムでも必ず問題を生成できるわけではありません。
- 入力・分岐・ループ・配列・計算・出力を含む初心者向けCプログラムを主な対象にしています。
- テスト入力が弱いと、誤りを入れても出力差が出ず、候補が採用されないことがあります。
- 配列添字バグなどは実行時の未定義動作を起こし得るため、コンパイル・実行検査で落とす方針にしています。
